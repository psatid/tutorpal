# Video meeting links for LINE class reminders

Research checked on 2026-10-21. This note compares a tutor-supplied URL with three provider API routes. Provider facts below come from first-party documentation; recommendations are product inferences for TutorPal.

## TutorPal starting point

- `Class` has no meeting-link field; `Schedule` and `RecurringSchedule` have `ON_SITE`/`ONLINE` types and notes. See [`schema.prisma`](../../backend/prisma/schema.prisma).
- Reminder discovery stores a rendered message, then delivery sends that stored message. Revalidation checks the schedule, start time, enrollment, and LINE eligibility, but does not rebuild changed content. A link changed after discovery could therefore be stale in a retry. See [`class-reminder.repository.ts`](../../backend/src/repositories/class-reminder.repository.ts), [`class-reminder.service.ts`](../../backend/src/services/class-reminder.service.ts), and [LINE class reminders](../features/line-class-reminders.md).
- Existing Google social login is tutor sign-in; the configured provider does not request Calendar or Meet API scopes. It is not evidence of consent or tokens usable for meeting creation. See [`auth-factory.ts`](../../backend/src/lib/auth-factory.ts) and [social login](../features/social-login.md).
- The integration screen labels Zoom and Google Meet “Coming soon.” See [`integrations-screen.tsx`](../../frontend/src/screens/integrations-screen.tsx). Recurring schedule edits can version future sessions from an effective date; link behavior will need an explicit policy for that boundary. See [recurring schedule editing](../features/recurring-schedule-editing.md).

## Options and provider constraints

| Route | What TutorPal can do | Main dependency and lifecycle issue |
| --- | --- | --- |
| Tutor pastes a URL | Store the supplied HTTPS join URL and include it in online-class details and LINE reminders. No provider API or provider OAuth is needed. | Tutor owns creation, access settings, validity, and replacement. A URL is not proof that a meeting exists or that a student can enter it. Google and Zoom both let hosts restrict entry. [Google Meet joining](https://support.google.com/meet/answer/9303069) · [Zoom scheduling/security settings](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0060700) |
| Google Calendar API conference data | Create or patch a *Calendar event* with `conferenceData.createRequest`, `conferenceSolutionKey.type=hangoutsMeet`, and `conferenceDataVersion=1`; read the resulting video entry point after asynchronous creation succeeds. [Create events and conferences](https://developers.google.com/workspace/calendar/api/guides/create-events) · [Event resource](https://developers.google.com/workspace/calendar/api/v3/reference/events) | Tutor must authorize Calendar event access and have write access to the target calendar. Google lists `calendar.events` as a narrower event-edit scope than full `calendar`; choose the minimum accepted by the chosen endpoint and verify in a prototype. Existing Google sign-in does not grant it. [Calendar scopes](https://developers.google.com/workspace/calendar/api/auth) · [Create events](https://developers.google.com/workspace/calendar/api/guides/create-events) |
| Google Meet REST API spaces | `spaces.create` directly returns a persistent space with `meetingUri`; its `spaces` methods can get/patch settings and end an **active conference**. This does not create a Calendar event or schedule a start time. [Meeting spaces overview](https://developers.google.com/workspace/meet/api/guides/meeting-spaces-overview) · [Meet REST methods](https://developers.google.com/workspace/meet/api/reference/rest/v2) | Requires user OAuth and the sensitive `meetings.space.created` scope. The published `spaces` methods have no space-delete operation, so cancellation needs a product policy (for example, hide the TutorPal link and change access settings where permitted), not an assumed API deletion. [Meet authorization](https://developers.google.com/workspace/meet/api/guides/authenticate-authorize) · [Meet REST methods](https://developers.google.com/workspace/meet/api/reference/rest/v2) |
| Zoom Meetings API | A user-managed OAuth app can call `POST /users/me/meetings`; the response supplies a participant `join_url`. `PATCH /meetings/{meetingId}` and `DELETE /meetings/{meetingId}` support later changes; a recurring occurrence can be addressed by `occurrence_id`. [Meetings API](https://developers.zoom.us/docs/api/meetings/) · [OAuth app types](https://developers.zoom.us/docs/integrations/) | Requires a Zoom host account with meeting scheduling enabled, a Zoom Marketplace OAuth app, user consent, and meeting create/update/delete scopes. Scheduling on behalf of another host also requires that host to grant scheduling privilege. Newly created apps use granular scopes (`meeting:write:meeting`, `meeting:update:meeting`, `meeting:delete:meeting` for the respective operations). Zoom may require account admin preapproval. [Create OAuth app](https://developers.zoom.us/docs/integrations/create/) · [Granular scopes](https://developers.zoom.us/docs/integrations/oauth-scopes-granular/) · [Scopes overview](https://developers.zoom.us/docs/integrations/oauth-scopes-overview/) · [Scheduling privilege](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0061749) |

### Google details

- Calendar conference creation is asynchronous: the initial event response may show `pending`; use `conferenceData.createRequest.status` and `entryPoints` before sending a generated URL. Use a fresh `requestId` for each new conference. Google warns that copying one Meet conference across unrelated events can expose details and recommends a unique conference per event. [Create events and conferences](https://developers.google.com/workspace/calendar/api/guides/create-events) · [Event resource](https://developers.google.com/workspace/calendar/api/v3/reference/events)
- Calendar recurrence has parent events and instances; an individual instance can be changed or cancelled, while “this and following” requires splitting the series. If TutorPal later mirrors its recurring schedules into Calendar, its effective-date versions will need mapping to those Calendar objects. [Recurring events](https://developers.google.com/workspace/calendar/api/guides/recurringevents)
- Meet spaces are persistent rooms rather than timed appointments. Only one active conference can run in a space at once. Google says a Meet meeting code generally expires 365 days after last use; Calendar-generated codes instead expire only when unused for 60 days **and** not attached to a future Calendar event. The space resource ID is safer to store than a meeting code because Google says codes can later be dissociated or reused. [Meeting spaces overview](https://developers.google.com/workspace/meet/api/guides/meeting-spaces-overview) · [Meeting code expiry](https://support.google.com/meet/answer/10710509)
- A Meet URL alone may still lead to an admission request. Access modes include Open, Trusted, and Restricted, with organization/admin policy affecting availability; a student outside the organizer's Calendar invite may need admission. Students without Google accounts can request to join, subject to organizer and admin settings. [Meet space access types](https://developers.google.com/workspace/meet/api/reference/rest/v2/spaces) · [Joining Meet](https://support.google.com/meet/answer/9303069)
- Google lists basic Meet scheduling for consumer and Workspace users, but edition, admin settings, and participant count affect meeting duration and features. Its help currently lists a one-hour limit for meetings with three or more participants on basic editions. [Meet feature availability](https://support.google.com/meet/answer/13396001)
- Current Calendar API quotas are 10,000 requests/minute/project and 600 requests/minute/user/project. Meet REST lists `spaces.create` at 100/minute/project and 10/minute/user/project. Both pages say standard API use has no additional cost, but describe possible charges above later-2026 thresholds; recheck before implementation or pricing claims. [Calendar quotas and pricing](https://developers.google.com/workspace/calendar/api/guides/quota) · [Meet quotas and pricing](https://developers.google.com/workspace/meet/api/guides/limits)
- Meet subscriptions via Google Workspace Events API and Cloud Pub/Sub report conference activity. They are useful for a later attendance/lifecycle feature, not necessary to put a link in a reminder. The Meet event guide does not establish Calendar-event reschedule reconciliation; that would require Calendar synchronization separately. [Meet events](https://developers.google.com/workspace/meet/api/guides/events-overview) · [Calendar recurrence](https://developers.google.com/workspace/calendar/api/guides/recurringevents)

### Zoom details

- Zoom's create response separates participant `join_url` from host `start_url`; send only `join_url` to students. The host `start_url` expires after two hours for regular users and can be refreshed via Get meeting. This is **not** a two-hour expiry of `join_url`. [Meetings API](https://developers.zoom.us/docs/api/meetings/) · [Create meeting workflow](https://developers.zoom.us/docs/isv/workflows/create-meeting/)
- A one-time scheduled meeting ID expires 30 days after its scheduled date, with reuse restarting the 30-day period. A recurring meeting ID expires after 365 days without a started occurrence. A pasted personal room URL has its own host-controlled lifecycle; TutorPal cannot promise indefinite validity. [Zoom meeting ID FAQ](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0065196)
- Basic/free hosts are generally limited to 40-minute meetings with participants, even on a paid account; the limit follows the host's license. This matters for hour-long tutoring sessions; TutorPal should not imply that API-created Zoom links lift the plan limit. [Zoom time limits](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0067966)
- Zoom describes passcodes and Waiting Rooms as access controls; a shared one-click join URL may embed the passcode. Treat the URL as a sensitive invitation, and let the host choose the admission policy. [Zoom passcode and Waiting Room guidance](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0067470)
- Zoom labels meeting create/update/delete endpoints `LIGHT` and documents a 100 create/update requests per day per host. Account-wide API rate limits also depend on plan; handle `429` and retry. [Meetings API](https://developers.zoom.us/docs/api/meetings/) · [API rate limits](https://developers.zoom.us/docs/api/rate-limits/)
- Zoom publishes `meeting.updated` and `meeting.deleted` events, including changes made outside an app. A later two-way integration can subscribe; webhook receivers need a public HTTPS endpoint, validation, and signature verification. Simple TutorPal-owned meeting creation does not require webhooks initially, but external host edits can otherwise make stored links/details stale. [Meeting webhooks](https://developers.zoom.us/docs/api/meetings/events/) · [Webhook setup](https://developers.zoom.us/docs/api/webhooks/)

I found sufficiently specific first-party material for these products. I did not find equally clear current TutorBird or TutorCruncher documentation during this pass, so no behavior is attributed to them here.

## Recommendation and phased choices

1. **First release: tutor supplied class link.** Add an optional HTTPS meeting URL to an online `Class`, show it in class/session details, and include it only in LINE reminders for `ONLINE` schedules. A class-level default suits repeated lessons; allow an explicit session override only when TutorPal needs per-session meetings. Do not interpret free-text notes as a join URL. Teachworks documents the same basic pattern, while both providers leave joining subject to host controls. [Teachworks Location Links](https://www.teachworks.com/addons/location-links) · [Meet joining](https://support.google.com/meet/answer/9303069) · [Zoom security](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0067470)
2. **Before shipping reminders:** decide whether reminder content is frozen at discovery or refreshed before send/retry. Given TutorPal's saved message snapshot, a tutor replacing the link after discovery can otherwise send an old URL. Rebuild or invalidate unsent delivery content on link changes, and test edit, cancellation, reschedule, and retry paths. This is a TutorPal behavior decision based on the repository files above.
3. **If demand justifies automatic creation:** choose either (a) Calendar-backed Meet when users also want Calendar events/invites, (b) direct Meet spaces when TutorPal needs a room URL without calendar synchronization, or (c) Zoom OAuth meeting creation for Zoom hosts. Store provider ID, host account, join URL, TutorPal schedule association, and synchronization state; define edits, disconnection, cancellation, recurrence, and failure fallback before enabling automatic reminders. These requirements follow from the distinct API resources and lifecycle methods documented above. [Calendar event conferences](https://developers.google.com/workspace/calendar/api/guides/create-events) · [Meet space methods](https://developers.google.com/workspace/meet/api/reference/rest/v2) · [Zoom meeting methods](https://developers.zoom.us/docs/api/meetings/)

### Open decisions

- Is the intended default one permanent room per class/tutor or a fresh room for each class occurrence? This changes data ownership and the provider route; Acuity offers distinct policies for group classes and recurring appointments. [Acuity video conferencing guide](https://help.acuityscheduling.com/hc/en-us/articles/16676895292941-Set-up-video-conferencing)
- Should TutorPal invite students to a Google Calendar event? LINE-only delivery of a Meet URL can require a student to ask for admission under a restricted/trusted host policy. [Meet access types](https://developers.google.com/workspace/meet/api/reference/rest/v2/spaces) · [Meet joining](https://support.google.com/meet/answer/9303069)
- Should a tutor's change to the class default affect all future sessions, only unsent reminders, or only newly created schedule versions? The current recurring-schedule model already has an effective-date boundary. See [recurring schedule editing](../features/recurring-schedule-editing.md).
- Which provider accounts and plans do pilot tutors actually use, and are their organizations willing to approve an OAuth app? Meet feature access and Zoom hosting ability depend on account/administrator settings. [Meet features](https://support.google.com/meet/answer/13396001) · [Zoom OAuth scopes](https://developers.zoom.us/docs/integrations/oauth-scopes-overview/) · [Zoom host privileges](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0075916)
