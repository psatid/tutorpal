# Frontend i18n Setup

This project uses **i18next** with **react-i18next** for internationalization.

## Structure

```
src/
├── i18n/
│   └── config.ts          # i18next initialization
├── locales/
│   └── en/                # English translations (current language)
│       ├── common.ts      # Shared translations (buttons, form labels, etc.)
│       ├── navigation.ts  # Navigation labels
│       ├── login.ts       # Login screen
│       ├── dashboard.ts   # Dashboard screen
│       ├── students.ts    # Students screen
│       ├── classes.ts     # Classes screen
│       └── schedules.ts   # Schedules screen
```

## Usage

### Basic Translation

```tsx
import { useTranslation } from "react-i18next";

function MyComponent() {
  const { t } = useTranslation(["dashboard"]);
  
  return <h1>{t("dashboard:title")}</h1>;
}
```

### Using Multiple Namespaces

```tsx
const { t } = useTranslation(["common", "students"]);

// From default/common namespace
t("buttons.save")

// From specific namespace
t("students:title")
```

### Interpolation (Variables)

```tsx
// Translation file:
// managingCount: "Managing {{count}} active scholars this term."

t("students:managingCount", { count: 24 });
// Output: "Managing 24 active scholars this term."
```

### Form Validation with Translations

```tsx
const { t } = useTranslation(["common"]);

const schema = z.object({
  email: z.email(t("common:form.invalidEmail")),
  password: z.string().min(1, t("common:form.required")),
});
```

## Adding a New Language

1. Create a new folder under `src/locales/` (e.g., `src/locales/es/`)
2. Copy all `.ts` files from `en/` and translate the values
3. Import the new translations in `src/i18n/config.ts`
4. Add the new language to the `resources` object

## Adding a New Screen

1. Create a new translation file: `src/locales/en/myscreen.ts`
2. Import it in `src/i18n/config.ts`
3. Add it to the `resources.en` object
4. Add the namespace to the `ns` array in the i18n init config
5. Use it in your screen component:

```tsx
const { t } = useTranslation(["myscreen"]);
```

## Namespaces

- **common**: Shared translations (buttons, form labels, loading states)
- **navigation**: Bottom navigation labels
- **login**: Login screen
- **dashboard**: Dashboard screen
- **students**: Students screen
- **classes**: Classes screen
- **schedules**: Schedules screen

## Best Practices

1. **One file per screen**: Keep translations organized by feature
2. **Use namespaces**: Access translations with `namespace:key` syntax
3. **Common namespace**: Put shared text (buttons, labels) in `common`
4. **Interpolation**: Use `{{variable}}` for dynamic content
5. **Type safety**: Translation files use `as const` for type inference
